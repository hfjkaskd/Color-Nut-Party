# 提现客户端流程补全

本轮修改位于 `C:/Projects/com.nut.sort.relax`，使用同一运行时代码处理 Editor、Android 和 iOS。新增条件界面是预先保存的 Prefab，运行时只绑定 Button、读取条件、更新文字和切换页面。

## 已接入

- 现金：内部 22、51 关完成边界，对应显示第 5、30 关；现金目标、引导标志、每日通关、登录天数、账户等级检查。
- 钻石：当前选择档位的钻石门槛、每日通关、独立钻石登录天数、账户等级检查；符合条件后复用收款账户及确认页。
- 按原版阶段判断，登录天数达到配置要求后跳过每日通关中间阶段；不会额外强制每天重新达到 10 次才允许继续。
- 账户确认时再次检查实时条件。条件发生变化会返回条件界面，不扣除余额，也不显示付款成功。
- 现金与钻石共用新的条件详情 Prefab，展示已满足、未满足及缺少目标数据的状态。
- 第 5 关完成、第二阶段未完成时，可进入已恢复的原版 TXProgress0Panel 与 TXTooFastHintPanel，保存原版阶段状态、时间及本地生成的队列字段，并返回提现入口。
- 条件不足时，继续游戏按钮直接关闭提现界面并恢复棋盘；第二关卡阶段显示 View next stage，进入对应进度页。关闭按钮返回此前的提现面板。
- 日历计数保存到 LocalWithdrawalData；同一天重启不重复增加登录天数，新的一天清零每日通关计数；设备日期倒退不重复计数。
- 美国引导结束边界读取独立配置，按已采集 `hg_psi=500` 设置绝对余额，保存一次性标志。待领奖励未领取时不提前发放；不对历史高关卡存档猜测补发，也不把美国样本套到其他地区。

## 尚需服务端的部分

动态 `TXTargetGold`、账户等级升级算法、其他地区初始化余额、完整服务器结算以及真实支付接口没有有效数据来源。客户端读取已有真实字段，不自行设置目标金额或虚构账户等级。目标缺失时明确显示 Awaiting account update，并阻止进入提现账户步骤。

原版排队字段仍按原版算法保存在本地，不作为真实支付队列或付款许可。当前显示改为 Application not submitted，不显示虚构客服服务状态或将随机号码作为真实客服编号。

本地提示页覆盖原版固定的“快于 99% 玩家”文案和 10/10 视频展示。视频计数来自现有激励视频成功回调，失败、无填充和插屏不计数。原版这个视频字段只参与界面显示，因此本轮不额外创造强制观看广告的提现门槛。

点击最终确认仍提示服务未连接。不会生成已付款记录，不会扣除现金或钻石。广告收益结算保持已有实现，本轮未用界面动画模拟广告成功。

## 检查与审阅

`LocalWithdrawalConditionsPlayValidation` 覆盖教程余额幂等及存档、跨日/倒退日期、关卡边界、未知金额、档位独立条件、原版登录优先级、实际现金/钻石入口、阶段及提示页面、账户确认复查和输入恢复。测试账户使用临时备份，退出时还原。

审阅图片位于本目录：`cash-effect.png`、`cash-replaced.png`、`diamond-effect.png`、`diamond-replaced.png`。effect 图片为新 Prefab 独立实渲效果，replaced 图片为实际游戏按钮打开后的画面。另有满足条件、第 30 关阶段和操作提示页面截图。

界面供用户确认；本轮不提交 Git、不发布、不构建替换安装包。
