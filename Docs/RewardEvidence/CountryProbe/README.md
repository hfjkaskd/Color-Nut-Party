# 巴西、印尼地区探测

2026-09-09，原版 `com.nut.sort.relax` 1.0.4。**已观察到不同注册地区的新身份收到不同奖励配置；仅给原有账号切换地区，配置保持相同。**

这些是服务器配置的原始数值，不是实际到账、可提现金额，也不是汇率比较。巴西与印尼的奖励配置有 7 个顶层字段不同，展示配置也不同。完整字段、解密规则和哈希见 [results.json](results.json) 及同目录 JSON。

两个巴西新身份的完整奖励配置、展示配置、解密规则均相同。共取得四个互不相同、且与原账号不同的服务器身份：BRA 两个、IDN 两个。第二个印尼身份确认注册成功，但多次采集仍未取得完整奖励配置，因此明确排除出奖励比较，不能宣称完成两个印尼奖励样本的复核。采集缺失不表示服务器没有返回。

原有账号分别设为 BR、ID 后，完整奖励配置和解密规则相同；仍为第 4 关，原始余额 557.58。截图显示分别为 `R$557,58`、`Rp557`，后者是显示格式截去小数，并非奖励减少。这个结果与“注册地区或账号保存的配置参与选择”一致，但尚不能确定服务器具体选择规则，也不能证明同国家不存在个性化或实验分组。

## 方法与边界

在原有可正常授权运行的安装上，备份 SDK 和游戏存档，改变 SDK 的国家缓存，并为新身份样本设置新的游戏请求标识、清除该测试副本中的游戏用户数据，由原版正常执行注册和配置请求。只读提取进程内已收到的应用层 JSON，未替换响应或修改奖励数值。注册响应中的原始身份不写入公开材料，只保留哈希用于验证独立性。

APK 的 `LocalPreference` 将 BR 映射为 BRA、ID 映射为 IDN；`NutSortAPI` 通过 `region_info` 发送 `c2c`、`c3c`。注册响应分别确认 BRA、IDN。原版截图也显示葡萄牙语/印尼语、对应货币符号和纸币图像，见 [画面对照](comparison.html)。

实际网络出口、广告标识、SDK 分组和 Adjust 归因没有主动更改，也没有独立当地设备。因此这是**地区参数和游戏身份的受控模拟，不是真实巴西/印尼买量用户**。初始化配置存在差异已被观察到；国家的严格因果效应仍需同条件交叉实验进一步隔离用户身份因素。此次未进行游戏通关或奖励领取，不能将初始化配置等同于全部未来结算响应。

一次启动可以取得该身份当次完整配置，不能据此一次获得服务器所有国家、实验分组、用户阶段或未来随机结算值。项目原有回放验证尚不包含本次印尼新配置，不能声称重建版已与这两类新身份完成界面和领取流程一致性验证，或已接通原版实时服务。
