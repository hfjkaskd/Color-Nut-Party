# Original Android statistics implementation audit

Read-only audit, 2026-10-12. No runtime or SDK changes were made for this audit. Sources are recovered ARM64 native instructions and bounded Ghidra pseudocode from `C:/Projects/Golden  Dragon Legend/reconstruction-nut/`; `dump.cs` / `game-schema.cs.txt` were used only for method/field names and offsets, not as executable C# implementations.

## Confirmed formulas

| UI field | Original implementation | Native evidence |
| --- | --- | --- |
| Players cleared today | `((int)(DateTime.Now - DateTime.Now.Date).TotalSeconds / 60) * 23`, using one captured local `Now` value | `native/9b7b50.asm`, `bodies-bounded/9b7b50.c`, `native/9bcf70.asm` |
| Average attempts, displayed level 1 or 2 | Literal `"1"` | `native/9b7068.asm`, 0x9B7420–0x9B7440 |
| Average attempts, displayed level > 2 | Stored `UserLocalData.TodayChallengeTimes` | `native/9b7068.asm`, 0x9B73AC–0x9B73F4 |
| Average withdrawal amount, displayed level 1 or 2 | Parse `GoldRewardTargetS2CData.bear_list[level == 1 ? 0 : 1].psi_value`, then the original currency formatter | `native/9b7068.asm`, 0x9B7444–0x9B74EC |
| Average withdrawal amount, displayed level > 2 | `UnityEngine.Random.Range(TXMinValue, TXMaxValue)` (float overload); bounds parsed from `PMDS2CData.casShowBt.Split('_')` | `native/9f230c.asm`, `native/9f209c.asm` 0x9F2130–0x9F21A0 |

These are display values generated by original client logic; they are not measured global player statistics. The pass count depends only on local device time, not player level, a random generator, or a backend count response. It increases by 23 per full minute and starts at 0 after local midnight. At 18:31, `1111 * 23 = 25553`, matching the count visible in the supplied original/reference comparison.

## Challenge count initialization

`UserMgr.ChallengeCount`, RVA `0x9C2BDC`, consists of integer `UnityEngine.Random.Range(5, 11)` (5 through 10). `ServerConfigData.Init`, RVA `0x9F2A2C`, assigns this to `TodayChallengeTimes` when the saved login date differs from the current UTC date; it also assigns when the stored value is nonpositive. This is a daily stored display sample, not a division of attempts by successful players. `TimeLSSUtil.IsToday`, RVA `0x9BCA68`, compares the Unix timestamp's UTC date to `DateTime.UtcNow.Date`.

## Date title and visibility

`PlayerInfo.Init`, RVA `0x9B7068`:

1. Resets its local position and hides its own GameObject.
2. Returns hidden when `user.ServerConfigData.LSS260820` (field offset 0x58) is true.
3. Sets localized child text, then returns hidden when `PMDInfo`'s static instance is null.
4. Formats the title with localization ID 31 and `TimeLSSUtil.GetTimeFormat("", "d")`.
5. Computes the three values above, enables the GameObject, creates `Prefabs/PlayerInfo/PMDSimple` under PMDPos, and initializes it using the displayed level.

`GetTimeFormat`, RVA `0x9B7884`, defaults the language to `CountryLssInfo.CountryLanguageCode`; it uses `TimeLSSUtil.Time / 1000`, `DateTimeOffset.FromUnixTimeSeconds(...).DateTime`, and `ToString("d", new CultureInfo(language))`. `Time`, RVA `0x9BC6C8`, is UTC milliseconds since the 1970-01-01 epoch initialized by constructor RVA `0x9BD048`. Therefore the title date is UTC-based, while the displayed pass count uses local wall-clock time. This inconsistency belongs to the original implementation.

## Current-project difference

The current project's `Assets/NutSort/Runtime/UI/OriginalPlayerInfo.cs` already reconstructs the primary original `Init(...)` branches, exposing pass count / date / random amount as supplied delegates. But `Assets/NutSort/Runtime/UI/OriginalWithdrawalPanel.cs:108` uses `InitUnavailable(...)` inside `InitLocal(...)`, unconditionally setting the date and all three values to the configured `--` placeholder. The missing statistics are therefore an intentionally disconnected local presentation path, not a clipping issue.

Reconnecting the original display logic should not describe these as real backend aggregates. Restoring the client formulas and the original configuration-driven random amount is distinct from adding a real statistics service. Retain existing money balances, rewards, SDK analytics, and gameplay progression.
