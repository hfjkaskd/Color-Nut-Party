# BizzaAnalytics 默认上报数据说明

本文说明组件自身的默认行为，不包含项目额外接入的业务埋点。

**启用条件**

`Release` 默认关闭，因此默认不会向服务器上报。配置有效、开启 `Release` 且命中采样后，才会自动采集并发送以下数据。上报比例默认 **100%**。

组件默认仅在 **Android 非 Editor 环境**自动初始化；其他环境需手动初始化或调用埋点接口触发初始化。

**自动事件**

| 事件 | 内容 | 触发时机 |
| --- | --- | --- |
| `login` | 初始化时的 UTC 时间戳；参数 `ip` 为本次查询到的公网 IP（IPv4 或 IPv6） | 每次初始化可上报的运行实例后，异步查询 IP，再产生一次登录事件 |

`login` 表示统计组件启动，不要求玩家完成账号登录；从后台恢复不会单独产生该事件。

公网 IP 通过 [ipify](https://www.ipify.org/) 的 `https://api64.ipify.org` 查询，超时为 3 秒，不阻塞游戏。失败、无效返回或查询期间暂停/退出时，仍记录 `login`，但 `ip` 为 `unknown`。该请求不携带打点 Token、用户标识或业务数据。

**自动用户属性**

| 字段 | 上报内容 |
| --- | --- |
| `playerID` | 本地随机生成并持久保存的玩家标识，与业务账号无绑定关系 |
| `device_model` | 设备型号；取不到时为 `unknown` |
| `language` | 系统语言 |
| `country` | 系统地区设置中的国家/地区代码；取不到时为 `unknown`，不通过 GPS 或 IP 定位 |
| `os_version` | 操作系统信息及版本 |
| `app_version` | 应用版本号 |
| `platform` | Unity 运行平台名称 |
| `game_duration` | 本地累计前台运行时长，单位为秒，向下取整；跨启动累加，不按天清零 |
| `update_ip` | 本次登录查询到的公网 IP，与 `login.ip` 相同；每次查询成功都上报，包括 IP 未变化的情况 |

除 `update_ip` 外，初始化时检查以上属性，首次记录或值发生变化时才生成上报记录。每条属性记录包含属性名、旧值、新值和 UTC 时间戳，首次记录的旧值为 `null`。IP 查询失败时不生成 `update_ip` 记录，也不覆盖之前的有效值。

`game_duration` 在暂停、退出或组件销毁时结算；后台暂停期间不计时，恢复后继续累计。

**每批请求附带的信息**

| 字段 | 含义 |
| --- | --- |
| `app_id` | 配置的应用标识 |
| `uid` | 本地随机生成并持久保存的统计用户标识，与 `playerID` 分开生成 |
| `batch_id` | 当前上报批次的随机标识 |
| `dt`、`part` | UTC 日期分区及分区编号 |
| `records` | 本批事件或用户属性变更记录 |

延迟补报的记录还会携带原始日期 `origin_dt`。`uid` 和 `playerID` 均由组件生成，不读取设备硬件唯一标识；本地统计状态清除后会重新生成。

**发送时机与范围**

- IP 查询完成后立即尝试发送 `login` 和启动时的用户属性，分别按事件和用户属性批次发送；后续用户属性变更仍约每 60 秒批量发送。
- 暂停、退出或组件销毁时，会结算时长并尝试发送剩余记录；发送失败的数据可在后续运行中重试，缓存记录默认保留 7 天。
- 关卡、按钮点击、广告、付费、分数等业务数据不会自动采集，需要通过 `Track` / `BTrack` 或 `UserProp` / `BUserProp` 手动接入。
- 当前组件没有默认采集广告标识、IMEI、GPS 位置、通讯录、手机号、崩溃日志或性能指标的逻辑。
- `ip` 是本次启动查询时的网络出口地址；缓存重试沿用该值。`country` 仍来自系统地区设置，不按 IP 推算国家。
